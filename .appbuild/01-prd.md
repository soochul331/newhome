# 01-PRD — 알부남 신목사 홈페이지 관리자 페이지

작성일 2026-10-08 · 작성 알부남 신목사 (기획 보조: Claude) · 상태: 초안(오너 확인 대기)

## 0. 한 줄 정의

홈페이지 운영자(알부남 신목사)가 코드를 만지지 않고 브라우저에서 **글·메뉴·섹션·페이지·글 목록·이미지**를 고치고, 고친 내용이 **자동으로 발행**되며, **언제든 이전 상태로 되돌릴 수 있는** 관리자 페이지.

## 1. 배경과 문제

- 현재 홈페이지(https://newhome-shin.netlify.app)는 `index.html` 한 파일에 글과 디자인이 함께 들어 있다. 문장 하나를 바꾸려 해도 HTML을 열고, 커밋하고, 네티파이에 다시 올려야 한다.
- 운영자는 개발자가 아니다. "일반 홈페이지 관리 업체가 주는 관리자 화면"처럼 로그인해서 고치고 저장하면 끝나야 한다.
- 동시에 my-homepage 스킬의 규칙(이름 표기, 3색, 존댓말, 지어낸 수치·후기 금지)이 관리자 화면에서 고친 글에도 지켜져야 한다.

## 2. 사용자

| 사용자 | 역할 | 수 |
|---|---|---|
| 운영자(오너) | 모든 내용 편집·발행·되돌리기 | 1명 (soochul331) |
| 편집 협력자(선택) | 글 초안 작성, 발행 권한 없음 | 0~2명, 나중에 |
| 방문자 | 공개 사이트 열람, 문의 양식 전송 | 불특정 |

## 3. 범위

### 3.1 MVP (1차 — 반드시)

| ID | 기능 | 설명 |
|---|---|---|
| F1 | 로그인 | 깃허브 계정으로 관리자 화면(/admin) 로그인. 허용된 계정만 |
| F2 | 사이트 기본 정보 편집 | 사이트 이름, 바이라인("알부남 신목사 · 늘푸른진건교회 교육목사"), 메타 설명, 교회·블로그 링크, 저작권 문구 |
| F3 | 메뉴 편집 | 상단 메뉴 항목의 이름·링크·순서·표시 여부 추가/삭제/정렬 |
| F4 | 홈 섹션 편집 | 히어로(라벨·제목·부제·버튼 2개), 나만의 질문, "이런 고민" 카드, "함께 하는 일" 카드, 소개(증거 4종), 최근 글, 문의 안내문. 각 섹션 **켜기/끄기와 순서 바꾸기** |
| F5 | 페이지 추가/삭제 | 일반 페이지(예: 강의 안내, 자료실)를 제목·주소·본문(서식 있는 글)으로 만들고 메뉴에 연결 |
| F6 | 글(소식) 관리 | 홈 "최근 글"에 보일 항목을 직접 관리: 제목·날짜·링크(네이버 블로그) 또는 본문. 추가·수정·삭제·순서 |
| F7 | 이미지 업로드 | 관리자 화면에서 이미지를 올리고 페이지·섹션에 넣기 |
| F8 | 초안·발행 흐름 | 저장 = 초안, "발행" 눌러야 공개. 발행 전 미리보기 |
| F9 | 자동 발행 | 발행하면 1~2분 안에 공개 사이트에 반영 |
| F10 | 되돌리기 | 모든 변경이 기록되고, 이전 버전으로 되돌릴 수 있다 |
| F11 | 규칙 검사 | 발행 전에 금지 표현(느낌표 남용, "지금 바로", 최상급 등)·이름 표기 오류를 자동으로 잡아 경고 |

### 3.2 2차 (MVP 다음)

| ID | 기능 |
|---|---|
| F12 | 문의 수신함 — 네티파이 폼에 들어온 문의를 관리자 화면에서 보기 |
| F13 | 관리자 화면 미리보기에 홈페이지 디자인(3색·글꼴) 그대로 적용 |
| F14 | 편집 협력자 초대(초안만 작성, 발행은 오너) |
| F15 | SEO 보조 — 페이지별 제목 태그·메타 설명 길이 검사, FAQ 구조화 데이터 자동 생성 |

### 3.3 하지 않는 것

- 회원 가입·로그인이 있는 방문자 기능(커뮤니티, 댓글)
- 결제·쇼핑
- 방문 통계 대시보드(네티파이 유료 기능. 필요하면 별도 도구를 2차 이후 검토)
- 관리자 화면 디자인을 처음부터 새로 만드는 일(1차는 검증된 CMS의 한국어 화면을 그대로 쓴다)

## 4. 수용 기준 (기능별)

| ID | 수용 기준 (모두 "~하면 ~한다"로 검증 가능) |
|---|---|
| F1 | /admin 접속 → "깃허브로 로그인" → 허용 계정이면 편집 화면, 아니면 거부 메시지. 로그아웃 가능 |
| F2 | 바이라인을 바꾸고 발행하면 푸터·메타 author가 함께 바뀐다 |
| F3 | 메뉴 항목을 추가해 순서를 2번째로 끌어 놓고 발행하면 공개 사이트 상단 메뉴가 그 순서로 보인다. "표시 안 함"으로 두면 사이트에서 사라지되 데이터는 남는다 |
| F4 | "최근 글" 섹션을 끄고 발행하면 홈에서 사라진다. 다시 켜면 내용 그대로 돌아온다. 섹션 순서를 바꾸면 그 순서로 렌더링된다 |
| F5 | 새 페이지 "강의 안내"를 만들고 주소 `/lecture/`로 발행하면 그 주소에서 열리고, 메뉴에 연결하면 메뉴에서 이동된다. 삭제하면 404가 된다 |
| F6 | 글을 3개 등록하면 홈 "최근 글"에 날짜 내림차순으로 3개가 보인다. 글에 링크가 있으면 새 창으로 외부 링크, 본문이 있으면 내부 페이지 |
| F7 | 이미지를 올리면 저장소 `src/media/`에 들어가고, 페이지에 넣으면 공개 사이트에서 표시된다. 10MB 초과 파일은 거부 |
| F8 | "저장"만 하면 공개 사이트가 바뀌지 않는다. "발행"을 눌러야 바뀐다. 발행 전 미리보기에서 변경 내용이 보인다 |
| F9 | 발행 후 네티파이 빌드가 자동으로 시작되고, 완료되면 공개 URL에 반영된다(목표 2분 이내, 빌드 로그로 확인) |
| F10 | 깃허브 커밋 기록에서 변경 내역이 보이고, 이전 커밋으로 되돌리면 사이트가 그 상태로 재발행된다 |
| F11 | 본문에 "지금 바로"를 넣고 발행하면 빌드가 실패하고 어떤 문장이 걸렸는지 로그에 나온다. 이름을 "신 목사"로 쓰면 경고가 나온다 |

## 5. 비기능 요구

- **비용:** 네티파이 Free + 깃허브 무료 범위 안에서 운영. 추가 월 비용 0원이 기본
- **보안:** 관리자 로그인은 깃허브 OAuth. 비밀번호를 직접 저장하지 않는다. 허용 계정 목록은 저장소 협력자 권한으로 관리
- **성능:** 공개 사이트는 정적 HTML. 지금과 같은 속도 유지
- **백업:** 모든 내용이 깃허브 저장소에 있으므로 저장소 자체가 백업
- **접근성·디자인:** DESIGN.md 토큰과 my-homepage 스킬 규칙을 템플릿에 고정. 운영자가 색·글꼴을 바꿀 수 없게 한다(일관성 보호)

## 6. 성공 지표

- 운영자가 문장 수정 → 발행까지 **코드를 열지 않고** 끝낸다
- 발행 뒤 공개 사이트 반영 2분 이내
- 규칙 검사(F11)로 금지 표현이 공개 사이트에 올라가는 일 0건
