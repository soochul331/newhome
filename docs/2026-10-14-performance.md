# 진단 결과에 따른 성능 정리

- 미사용 Noto Serif KR CSS의 전역 로딩을 제거. 실제 serif 서식이 저장되어 있거나 해당 글꼴을 관리자에서 선택할 때만 로딩합니다.
- 공개 화면의 사용자 지정 서식이 없으면 visual-layout.js도 생략합니다. 현재 홈에는 사용자가 저장한 16px 서식과 푸터 문구 재정의가 있으므로 해당 스크립트를 유지합니다.
- studioTargets는 전체 텍스트를 반복 비교하거나 innerText로 레이아웃을 읽는 대신, textContent 색인을 만들어 저장된 서식 키만 찾도록 개선했습니다. 관리자에서는 전체 편집 대상으로 사용합니다.
- work-source-transform에서 visibility 키프레임을 제거. opacity와 transform 연출 유지.
- Netlify 프로젝트 설정의 Powered by Netlify badge를 끄고 저장 확인. 공개 페이지의 삽입 HUD 작업을 줄이기 위한 변경입니다.
- 최신 관리자 커밋 3a9b6df와 69d0047의 문구·크기 변경을 보존했습니다.
- 빌드, 테마·편집·스튜디오 검사 통과. 로컬 브라우저에서 외부 폰트 CSS 없음, 저장된 16px 서식 8개 요소 적용, 탭 동작 및 콘솔 오류 없음을 확인했습니다.
- Lighthouse 점수 및 밀리초 단위 개선량은 재측정하지 않았습니다. 제공된 진단 수치를 개선 후 측정치로 사용하지 않습니다.

## 렌더링 차단 및 네트워크 종속 요청 후속 정리
- 현재 모션 스튜디오의 theme-beagle / motion-demo / text-layout CSS를 빌드 시 HTML `<style>`에 함께 포함합니다. 관리자 미리보기도 동일한 CSS 자료를 받습니다.
- 해당 화면에서 CSS 요청 3개를 생략합니다. 이 작은 사이트에서는 첫 방문의 추가 요청을 없애는 쪽을 선택했습니다. 대신 HTML에 CSS가 포함되어 문서 크기가 늘며, 페이지 간 CSS 파일 캐시 공유 이점은 줄어듭니다.
- CSS 주석을 빌드 결과에서 제거합니다. CSS 원본은 그대로 유지합니다.
- 현재 테마에서 사용하지 않는 fonts.googleapis.com / fonts.gstatic.com preconnect를 제거합니다. 다른 테마 또는 저장된 serif 서식에서 폰트가 필요한 경우에는 유지합니다.
- 빌드·관리자·다른 테마 검사 및 새 렌더링 요청 검사 통과. Lighthouse의 460ms는 제공된 진단의 예상값이며 실측 개선량으로 주장하지 않습니다.

## 로고 이미지, DOM, 첫 화면 표시 후속 정리
- 가로 로고를 2164×727 PNG(877,599B)에서 600×202 WebP(7,148B)로 교체. 세로 로고도 92,726B PNG에서 5,750B WebP로 교체. 원본은 보관합니다.
- 공개 페이지는 저장된 캔버스 재정의 키에 해당하는 텍스트만 span으로 감쌉니다. 관리자는 기존처럼 모든 텍스트를 편집 대상으로 만듭니다.
- 로컬 DOM 요소 497개, 캔버스 래퍼 2개를 확인했습니다. 기존 진단에는 697개가 표시되어 있었습니다.
- 저장된 16px 서식은 8개 요소에 유지되며, 모바일 360px 실제 콘텐츠 폭에서 가로 넘침이 없음을 확인했습니다.
- 메인 제목의 등장 애니메이션을 제거해 즉시 표시합니다. 탭·결과물·스크롤 모션은 유지합니다.
- Lighthouse LCP 개선 시간은 재측정하지 않았습니다.
