## 3. 나의 목소리

### 3.1 기본 원칙

- **존댓말.** "~합니다", "~입니다", "~해 보세요". 반말·"~함"체·"~하라" 명령형은 쓰지 않습니다.
- **보통 문장.** 한 문장에 생각 하나, 20자 안팎. 쉼표로 길게 잇지 않습니다. 짧게 쓴다고 명사 나열("AI 활용. 신학적 분별. 실습.")로 끝내지 않습니다.
- **컨설턴트의 자리.** 가르치되 내려다보지 않습니다. 겁주지 않고 부추기지 않습니다. 방문자가 "나도 할 수 있겠다"고 느끼게 씁니다.
- **성장의 어조.** 천천히, 꾸준히. 재촉하지 않습니다.
- **분별을 말로 보여줍니다.** AI의 쓸모와 한계를 함께 말합니다. 장점만 늘어놓지 않습니다.

### 3.2 자주 쓰는 표현

| 표현 | 자리 |
|---|---|
| **감사합니다** | 페이지 끝, 신청 완료 화면, 문의 응답. 가장 자주 쓰는 마무리 말 |
| 함께 해 보겠습니다 | 실습·강의 안내 시작 |
| 천천히 가도 괜찮습니다 | 처음 오신 분 격려 |
| 분별하며 사용합니다 | AI 활용 원칙 |
| 한 걸음씩 | 과정·성장을 말할 때 |

### 3.3 버튼·링크 글자

- 동사로 끝나는 짧은 존댓말: "시작하기", "강의 보기", "자료 받기", "문의하기", "블로그 가기".
- 느낌표를 붙이지 않습니다. "지금 바로", "무료로" 같은 재촉·유인 수식어를 붙이지 않습니다.

### 3.4 하지 말 것 (금지 목록)

| 금지 | 이유 | 대신 |
|---|---|---|
| **지어낸 수치** ("목회자 90%가…", "3배 빨라집니다", "수강생 500명") | 출처 없는 숫자는 신뢰를 깨뜨립니다. 교육자가 가장 피해야 할 일 | 출처 있는 숫자만 쓰고 출처를 밝힙니다. 없으면 숫자 없이 씁니다 |
| **지어낸 후기** (가상의 수강생 이름·소감·별점) | 없는 사람의 말을 만들면 사이트 전체가 거짓이 됩니다 | 실제 후기를 사용자에게 받아 이름 표기 동의 후 씁니다. 없으면 후기 영역 자체를 만들지 않습니다 |
| 과장·최상급 ("혁명적", "완벽한", "국내 최초", "유일한") | 분별의 태도와 어긋납니다 | "도움이 됩니다", "줄어듭니다" |
| 공포 마케팅 ("뒤처집니다", "안 하면 큰일") | 두려움을 푸는 사람이 두려움을 팔 수 없습니다 | "지금부터 시작해도 충분합니다" |
| 재촉 ("지금 바로", "마감 임박", "서두르세요") | 성장은 천천히 꾸준히 갑니다 | 날짜와 조건만 알립니다 |
| 느낌표·이모지 남용 | 가벼워 보입니다 | 마침표. 이모지는 페이지에 하나 이하 |
| 영어 약어 그대로 (LLM, RAG, AX, 프롬프트 엔지니어링) | 처음 오신 분이 혼란을 느낍니다 | 한국어로 풀고 괄호에 원어를 처음 한 번만 |
| AI를 사람처럼 말하기 ("AI가 생각합니다", "AI가 알고 있습니다") | 신학적 분별을 흐립니다 | "AI가 생성합니다", "AI가 출력합니다" |
| 신앙 언어의 상업적 사용 ("축복받은 가격", "은혜로운 할인") | 경계를 지킵니다 | 가격·조건은 사실만 |

## 4. 나의 색깔

세부 토큰은 DESIGN.md가 원본입니다. **지금 공개 사이트는 "애플 스타일" 테마**(2026-10-09 적용)이며, 관리자 화면 "화면 테마"에서 기본 테마로 되돌릴 수 있습니다. 4.1~4.3절은 애플 스타일 기준이고, 기본 테마로 작업할 때는 DESIGN.md 1~3절을 따릅니다.

### 4.1 색 — 브랜드 3색을 애플의 역할에 대응

```css
:root {
  --canvas:    #FFFFFF;   /* 흰 구획 */
  --parchment: #F6F7FB;   /* 연한 회색 구획·바닥글 */
  --ink:       #141B34;   /* 글자, 어두운 구획 바탕 */
  --accent:    #2747D6;   /* 유일한 강조색 */
  --ink-muted: #5B5F71;   /* 보조 글자(글자색 70%) */
  --accent-on-dark: #8FA5FF; /* 어두운 구획 위 링크만 */
  --hairline:  rgba(20,27,52,.10);
}
```

**강조색의 의미 — 성장: 천천히 그러나 꾸준히.**
강조색은 "다음 한 걸음"을 가리키는 자리(주 버튼·링크)에만 씁니다. 두 번째 강조색과 그라데이션은 만들지 않습니다. 구획은 흰색·연한 회색·어두운 남색으로 번갈아 나오며, 색이 바뀌는 곳이 곧 구분선입니다.

대비는 실측 기준 모두 WCAG AA 이상입니다(글자/흰 바탕 16.99:1, 강조/흰 바탕 7.10:1, 남색 위 흰 글자 16.99:1, 남색 위 링크 7.28:1, 보조 글자/흰 바탕 6.32:1).

### 4.2 글꼴

```css
--font-display: "SF Pro Display", system-ui, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif;
--font-text:    "SF Pro Text",    system-ui, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif;
```

본문은 17px 아래로 내리지 않고, 13px보다 작은 글자는 쓰지 않습니다. 제목에 색을 입히지 않습니다.

### 4.3 모양

- **버튼.** 알약 모양 두 종류. 주 버튼(강조색 바탕·흰 글자), 보조 버튼(투명·강조색 글자와 테두리). 높이 44px 이상. 그라데이션·그림자 버튼 금지.
- **카드.** 그림자 없음. 모서리 18px, 옅은 1px 테두리, 안쪽 여백 24px 이상. 카드 안에 카드 금지. 카드 하나에 제목·두세 줄·행동 하나까지. 격자는 최대 3열.
- **구획.** 화면 폭 전체, 위아래 여백 80px(휴대폰 48px). 각 구획 제목은 가운데 정렬.
- **여백.** 넉넉하게. 한 화면에 한 가지 메시지. 본문 한 줄은 한글 30~40자(약 640~760px) 안에서 끊습니다.
- **이미지.** 밝고 조용한 톤. 이미지 위에 글자를 얹지 않습니다. 생성 이미지 프롬프트에는 "clean white and soft off-white #F6F7FB, deep navy #141B34, single blue accent #2747D6, calm, minimal, Apple-like product photography lighting"을 넣습니다.

### 4.4 페이지 기본 골격 (홈)

1. **히어로** — H1(정체성 문장을 줄인 한 줄) + 부제(신뢰 축: 누구를 위해) + 주 버튼 하나 + 보조 버튼 하나
2. **나만의 질문** — "AI 시대, 교회는 무엇을 맡기고 무엇을 지켜야 할까요?" 한 줄. 애플 스타일에서는 어두운 남색 구획에 크게, 덧붙이는 말은 두세 문장
3. **이런 분을 위해** — 가치 축(어떻게 써야 할지 모르겠는 분)을 세 가지 상황으로
4. **무엇을 함께 하나** — 신학적 분별 · 현장 실습 · 온라인 활동, 카드 3개
5. **나는 누구인가** — 증거 네 가지를 한 문장씩 + 두 링크
6. **최근 글** — 처치AI랩 블로그 글 3개(제목·날짜·링크, 실제 글만)
7. **마무리** — "감사합니다" + 문의 버튼 + 푸터(신수철 목사 · 늘푸른진건교회 교육목사 · 링크 2개)

## 5. 글쓰기 규칙 — SEO·AEO·GEO

검색엔진(SEO), 답변엔진(AEO), 생성형 AI 검색(GEO) 모두에 같은 원리가 통합니다: **질문에 바로, 사실로, 출처를 달아 답한다.** 이것은 나의 말투 원칙(직답·사실·분별)과 같은 방향이므로 억지로 맞출 필요가 없습니다.

### 5.1 질문형 소제목

- H2·H3는 방문자가 실제로 검색창에 칠 **질문 문장**으로 씁니다.
  - 예: "목회에 AI를 써도 괜찮을까요?", "설교 준비에 AI를 어디까지 쓸 수 있나요?", "신학적 분별이란 무엇인가요?"
- 한 페이지에 질문형 소제목 3~6개. 한 소제목 아래 답은 한 가지 주제만 다룹니다.
- 질문에는 키워드 3개(목회 AI·신학적 분별·교회교육) 중 하나가 자연스럽게 들어가도록 합니다. 억지로 반복하지 않습니다.

### 5.2 첫 문장 직답

- 모든 소제목 바로 아래 **첫 문장이 답**입니다. 배경 설명·인용·질문 되묻기로 시작하지 않습니다.
  - 나쁜 예: "많은 목회자들이 이 질문을 하십니다. 사실 이 문제는…"
  - 좋은 예: "괜찮습니다. 다만 무엇을 맡기고 무엇을 맡기지 않을지 먼저 정해야 합니다."
- 첫 문장은 40자 안팎, 그 자체로 발췌(스니펫)되어도 뜻이 통해야 합니다.
- 직답 뒤에 이유 1~2문장, 그다음 실습·예시 순서로 씁니다.

### 5.3 출처·숫자·링크

- **숫자는 출처가 있을 때만.** 출처 없는 숫자는 쓰지 않습니다(3.4절). 숫자를 쓸 때는 같은 문장이나 바로 다음 문장에 출처 이름과 링크를 붙입니다.
  - 형식: "…입니다(출처: 기관명, 연도, 링크)."
- **나의 경험·결과물을 1차 출처로.** 블로그 글, 직접 만든 도구, 교회 사역 경험은 그 자체가 출처입니다. 블로그의 해당 글로 링크합니다.
- **외부 링크는 신뢰할 수 있는 1차 자료만.** 공식 문서, 학술·기관 자료, 원문. 요약 블로그·커뮤니티 글은 출처로 쓰지 않습니다.
- **내부 링크.** 페이지마다 관련 페이지·블로그 글로 가는 링크를 2개 이상 둡니다. 링크 글자는 "여기"가 아니라 가는 곳의 제목으로 씁니다.
- **메타 정보.** 페이지마다 제목 태그(30자 안팎, 키워드 하나 포함), 메타 설명(80~110자, 첫 문장 직답과 같은 내용), author에 "신수철 목사 (Church AI Lab 디렉터)".
- **구조화.** FAQ 형식의 질문·답은 FAQ 스키마(JSON-LD)로, 소개 페이지는 Person 스키마로 표시합니다. 스키마의 모든 값은 2.5절 증거표 안의 사실만 씁니다.
- **문단 길이.** 한 문단 3~4문장. 목록은 항목 3~5개. 표는 비교할 것이 둘 이상일 때만.
